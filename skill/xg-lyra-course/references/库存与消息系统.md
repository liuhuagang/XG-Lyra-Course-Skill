# Inventory & Message System

## Overview

The inventory system and message system together form Lyra's infrastructure for **item management** and **event communication**. The inventory system handles item definition, storage, and consumption; the message system provides a loosely-coupled cross-system communication mechanism; and the game phase system uses GAS to drive game flow phase transitions.

---

## Inventory System: Four-Layer Architecture

**File**: `Source/LyraGame/Inventory/LyraInventoryManagerComponent.h`

The inventory system is divided into four layers:

```
Item Definition Layer
  ULyraInventoryItemDefinition —— Item template (UObject, Blueprintable, Abstract)
    └── Fragments[] —— Item fragment array (EditInlineNew)

Item Instance Layer
  ULyraInventoryItemInstance —— Runtime item instance (Replicated)
    ├── ItemDef —— Points to definition
    └── StatTags —— Stat tag stack

Inventory List Layer
  FLyraInventoryList —— FFastArraySerializer
    └── Entries[] —— FLyraInventoryEntry
          ├── Instance -> ULyraInventoryItemInstance
          └── StackCount —— Stack count

Inventory Manager Layer
  ULyraInventoryManagerComponent —— UActorComponent
    └── InventoryList —— Item list
```

### Definition Layer: ULyraInventoryItemDefinition

**File**: `Source/LyraGame/Inventory/LyraInventoryItemDefinition.h`


### Fragment System

`ULyraInventoryItemFragment` is an `EditInlineNew` abstract base class that extends item functionality through composition:

```cpp
UCLASS(Abstract, DefaultToInstanced, EditInlineNew)
class ULyraInventoryItemFragment : public UObject
{
    GENERATED_BODY()

public:
    // Callback when an instance is created
    virtual void OnInstanceCreated(ULyraInventoryItemInstance* Instance) const;
};
```

Add Fragment subclasses in the item definition Blueprint to extend functionality, such as weapon fragments adding damage attributes, or consumable fragments adding recovery effects.

### Inventory List Layer: FLyraInventoryList

Inherits `FFastArraySerializer` for network delta replication:

```
FLyraInventoryEntry
  ├── Instance : ULyraInventoryItemInstance (Replicated)
  └── StackCount : int32 (Replicated)

FLyraInventoryList
  ├── GetAllItems()
  ├── AddEntry(ItemClass, StackCount)
  ├── AddEntry(Instance)
  └── RemoveEntry(Instance)
```

### Manager Layer: ULyraInventoryManagerComponent

Main API entry points:

| Method | Description |
|--------|-------------|
| `CanAddItemDefinition(ItemDef, StackCount)` | Check if an item can be added |
| `AddItemDefinition(ItemDef, StackCount)` | Add item by definition, returns instance |
| `AddItemInstance(Instance)` | Add instance directly |
| `RemoveItemInstance(Instance)` | Remove instance |
| `GetAllItems()` | Get list of all instances |
| `ConsumeItemsByDefinition(ItemDef, NumToConsume)` | Consume specified quantity of items |

### ALyraWeaponSpawner: Weapon Spawner

**File**: `Source/LyraGame/Weapons/LyraWeaponSpawner.h`

Actor that spawns pickupable weapons in the scene, supporting a pickup-cooldown-respawn cycle:

```cpp
UCLASS()
class ALyraWeaponSpawner : public AActor
{
    ULyraWeaponPickupDefinition* WeaponDefinition;
    bool bIsWeaponAvailable;              // Replicated
    float CoolDownTime;
    float CheckExistingOverlapDelay;

    UCapsuleComponent* CollisionVolume;
    UStaticMeshComponent* PadMesh;
    UStaticMeshComponent* WeaponMesh;
};
```

#### Pickup-CoolDown-Respawn Flow

```
OnOverlapBegin (player enters collision)
  → Check bIsWeaponAvailable
  → AttemptPickUpWeapon(Pawn)
    → GiveWeapon(WeaponItemClass, Pawn) (BlueprintImplementableEvent)
    → Creates InventoryItemInstance, adds to player inventory
  → StartCoolDown()
    → SetWeaponPickupVisibility(false)
    → bIsWeaponAvailable = false
    → Start cooldown timer

Cooldown complete
  → bIsWeaponAvailable = true
  → SetWeaponPickupVisibility(true)
  → PlayRespawnEffects() (BlueprintNativeEvent)
  → CheckForExistingOverlaps() (check if any Pawn is waiting on the pad)
```

#### ULyraPickupDefinition / ULyraWeaponPickupDefinition

DataAssets defining pickup properties:

| Field | Type | Description |
|-------|------|-------------|
| `InventoryItemDefinition` | TSubclassOf | Item definition to add on pickup |
| `DisplayMesh` | UStaticMesh | Pickup display mesh |
| `SpawnCoolDownSeconds` | float | Respawn cooldown time |

Weapon pickup definition additionally includes `WeaponMeshOffset` and `WeaponMeshScale`.

## GameplayMessageRouter: Message Routing System

### Plugin Layer

**File**: `Plugins/GameplayMessageRouter/Source/GameplayMessageRuntime/Public/GameFramework/GameplayMessageSubsystem.h`

As a `UGameInstanceSubsystem`, provides a GameplayTag-based publish-subscribe messaging mechanism:

```cpp
class UGameplayMessageSubsystem : public UGameInstanceSubsystem
{
    // Broadcast message, supports parent tag traversal
    void BroadcastMessage(FGameplayTag Tag, const TSharedPtr<void>& Message);

    // Register listener
    void RegisterListener(FGameplayMessageListenerParams& Params);

    // Blueprint version
    UFUNCTION(BlueprintCallable)
    void K2_BroadcastMessage(FGameplayTag Tag, const int32& Message);
};
```

`FGameplayMessageListenerParams` configuration parameters:

```cpp
struct FGameplayMessageListenerParams
{
    FGameplayTag Tag;                                                  // Tag to listen for
    TFunction<void(FGameplayTag, const TSharedPtr<void>&)> Callback;   // Callback
    EGameplayMessageMatch MatchType;                                   // ExactMatch / PartialMatch
};
```

### Application Layer: FLyraVerbMessage

**File**: `Source/LyraGame/Messages/LyraVerbMessage.h`

Core message structure describing "who (Instigator) did what (Verb) to whom (Target)":

```cpp
USTRUCT(BlueprintType)
struct FLyraVerbMessage
{
    FGameplayTag Verb;                    // Action tag
    TObjectPtr<UObject> Instigator;       // Initiator
    TObjectPtr<UObject> Target;           // Target
    FGameplayTagContainer InstigatorTags; // Initiator tags
    FGameplayTagContainer TargetTags;     // Target tags
    FGameplayTagContainer ContextTags;    // Context tags
    double Magnitude;                     // Magnitude value
};
```

### FLyraVerbMessageReplication: Message Replication

**File**: `Source/LyraGame/Messages/LyraVerbMessageReplication.h`

Server-to-client message replication mechanism based on `FFastArraySerializer`:

```
Server calls AddMessage()
  → Message added to CurrentMessages array, marked dirty
  → FastArray auto-syncs to clients via NetDeltaSerialize
  → Client PostReplicatedAdd / PostReplicatedChange
    → Locally re-broadcasts through UGameplayMessageSubsystem
    → Local listeners receive the message
```

### FLyraNotificationMessage: Notification Message

### UGameplayMessageProcessor: Message Processor Base Class

**File**: `Source/LyraGame/Messages/GameplayMessageProcessor.h`

Template method pattern, subclasses only need to override `StartListening()`:

```
BeginPlay() → StartListening()  // Subclass registers message listeners here
EndPlay()   → StopListening()   // Automatically cleans up all ListenerHandles
```

## Game Phase System

### Architecture Overview

The game phase system uses GAS abilities to drive game flow phase transitions, supporting phase nesting, observer patterns, and phase mutual exclusion.

### ULyraGamePhaseAbility: Phase Ability

**File**: `Source/LyraGame/AbilitySystem/Phases/LyraGamePhaseAbility.h`

```cpp
UCLASS(Abstract, HideCategories = Input)
class ULyraGamePhaseAbility : public ULyraGameplayAbility
{
    GENERATED_BODY()

public:
    // GameplayTag bound to this phase
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Lyra|Game Phase")
    FGameplayTag GamePhaseTag;

    const FGameplayTag& GetGamePhaseTag() const { return GamePhaseTag; }
};
```

The hierarchical structure of Tags determines parent-child relationships between phases. Editor color is blue-green `FColor(0, 96, 128)`.

### ULyraGamePhaseSubsystem: Phase Subsystem

**File**: `Source/LyraGame/AbilitySystem/Phases/LyraGamePhaseSubsystem.h`

```cpp
class ULyraGamePhaseSubsystem : public UWorldSubsystem
{
    // Activate a phase
    void StartPhase(TSubclassOf<ULyraGamePhaseAbility> PhaseAbility,
                    FLyraGamePhaseDelegate PhaseEndedCallback);

    // Observe phase start (calls immediately if already active)
    void WhenPhaseStartsOrIsActive(FGameplayTag PhaseTag, EPhaseTagMatchType MatchType,
                                   const FLyraGamePhaseTagDelegate& WhenPhaseActive);

    // Observe phase end
    void WhenPhaseEnds(FGameplayTag PhaseTag, EPhaseTagMatchType MatchType,
                       const FLyraGamePhaseTagDelegate& WhenPhaseEnd);

    // Check if phase is active
    bool IsPhaseActive(const FGameplayTag& PhaseTag) const;

private:
    TMap<FGameplayAbilitySpecHandle, FLyraGamePhaseEntry> ActivePhaseMap;
    TArray<FPhaseObserver> PhaseStartObservers;
    TArray<FPhaseObserver> PhaseEndObservers;
};
```

### Activation Flow

```
Blueprint calls K2_StartPhase
  → ULyraGamePhaseSubsystem::StartPhase
  → Gets GameState's ASC
  → GiveAbilityAndActivateOnce (GA activates)
  → GA::ActivateAbility
    → PhaseSubsystem::OnBeginPhase
    → Mutual exclusion check
```

### Phase Mutual Exclusion Logic

```
Current active Game.A
- New phase Game.A.1 → Game.A stays active (parent phase), Game.A.1 activates (child phase)
- New phase Game.B   → Game.A is canceled (sibling branch)
- New phase Game.A.2 → Game.A stays active, Game.A.1 canceled (same-level replacement)
```

Core logic: `!IncomingPhaseTag.MatchesTag(ActivePhaseTag)` → cancel current phase if not a child relationship.

### Typical Phase Examples

| Phase | Behavior |
|-------|----------|
| Warm-up phase | Applies global invulnerability GE_PregameLobby, plays waiting sound effects, 3-second countdown |
| Combat phase | Activates character Reset ability, clears scene grenades and weapon spawners |
| Scoring phase | Global invulnerability disables abilities, ServerTravel to next match after delay |

## Key Design Points

1. **Four-layer inventory architecture** — Definition / Instance / List / Manager layers with clear responsibility separation, Fragment system provides composable extensibility
2. **FastArray network sync** — FLyraInventoryList and FLyraVerbMessageReplication both use FFastArraySerializer for delta replication
3. **IPickupable interface** — Unified contract for pickupable items, supports both Template (generate by definition) and Instance (direct reference) pickup modes
4. **Two-layer message system design** — Plugin layer provides generic Tag message routing, application layer builds domain protocol on VerbMessage
5. **Message replication decoupling** — Server replicates raw messages via FastArray, client re-broadcasts through local message system
6. **GamePhase based on GAS** — Phase transitions driven by GA, Tag hierarchy natively supports phase nesting and mutual exclusion
7. **Observer pattern** — WhenPhaseStartsOrIsActive / WhenPhaseEnds support executing custom logic on phase changes
