# Equipment & Weapon System

## Overview

Lyra's equipment system adopts a **three-tier architecture** that separates equipment definition, runtime instance, and management. Through the AbilitySet mechanism, equipment ability granting and revocation are automated.

---

## Three-Tier Architecture

```
ULyraEquipmentDefinition (Definition Layer)
    │  Data asset, describes equipment type and associated AbilitySets
    │  Stores configuration only, no runtime state
    │
    ▼
ULyraEquipmentInstance (Instance Layer)
    │  Runtime object, holds SpawnedActor and GrantedAbilitySets
    │  Each equipment instance exists independently
    │
    ▼
ULyraEquipmentManagerComponent (Management Layer)
    │  Manages equipment list (FastArray network replication)
    │  Provides equip/unequip interface
```

## Tier 2: EquipmentInstance

**File**: `Source/LyraGame/Equipment/LyraEquipmentInstance.h`

```cpp
UCLASS(BlueprintType)
class ULyraEquipmentInstance : public UObject
{
    GENERATED_BODY()

public:
    // Get the Pawn this equipment belongs to
    UFUNCTION(BlueprintPure)
    APawn* GetTypedPawn() const;

    // Get the equipment's Actor (e.g., weapon mesh)
    UFUNCTION(BlueprintPure)
    AActor* GetSpawnedActor() const;

    // Equip to the specified Pawn
    virtual void OnEquipped(APawn* Owner);

    // Unequip from the Pawn
    virtual void OnUnequipped();

    // Get the AbilitySet Handles granted by this equipment (for revocation on unequip)
    const TArray<FGameplayAbilitySpecHandle>& GetGrantedAbilityHandles() const
    {
        return GrantedAbilityHandles;
    }

protected:
    // Spawned Actor (e.g., weapon mesh)
    UPROPERTY()
    TObjectPtr<AActor> SpawnedActor;

    // Handles recorded when AbilitySets are granted
    TArray<FGameplayAbilitySpecHandle> GrantedAbilityHandles;
};
```

## Equipment Switch Flow

```
ULyraQuickBarComponent::SetActiveSlot(NewSlot)
    │
    ├── Unequip old equipment
    │   → EquipmentManagerComponent::RemoveEquipment(OldEquip)
    │   → OldEquip::OnUnequipped()
    │   → ASC::RemoveAbility(OldEquip.GetGrantedAbilityHandles())
    │   → OldEquip marked for pending kill
    │
    └── Equip new equipment
        → EquipmentManagerComponent::AddEquipment(DefinitionClass)
        → NewEquip created
        → NewEquip::OnEquipped(OwnerPawn)
        → SpawnEquipmentActor (spawns weapon mesh)
        → Definition.AbilitySetsToGrant → ASC::GiveAbility
        → GrantedAbilityHandles recorded on NewEquip
```

## Spread/Heat System

### Core Interface

**File**: `Source/LyraGame/AbilitySystem/LyraAbilitySourceInterface.h`

```cpp
struct ILyraAbilitySourceInterface
{
    virtual float GetDistanceAttenuation() const = 0;
    virtual float GetSpreadAngleMultiplier() const = 0;
};
```

### Spread Angle Calculation

```
Current spread angle = Heat × SpreadAngleCurve(Heat)

Where SpreadAngleCurve is a UCurveFloat mapping Heat → SpreadAngle
```

### Precision Multiplier System

The final shot dispersion is determined by 4 multipliers:

| Multiplier | Description |
|------------|-------------|
| SpreadRateMultiplier | Heat growth rate |
| SpreadAngleMultiplier | Base spread angle scaling |
| StandStillSpreadMultiplier | Precision compensation when standing still |
| CrouchingSpreadMultiplier | Precision compensation when crouching |

```
Final spread angle = BaseSpread × SpreadAngleMultiplier × StandStillMultiplier × CrouchingMultiplier
```

## SourceObject Tracing

EquipmentInstance serves as the GA's SourceObject, allowing the GA to trace back to the equipment that granted it:

```
Inside GA, call GetSourceObject()
    → Returns ULyraEquipmentInstance
    → EquipmentInstance.GetEquipmentDefinition()
    → Returns ULyraEquipmentDefinition (data asset configuration)
    → Reads weapon range, damage type, and other configuration data
```

This allows the same GA to be reused by multiple weapons, differentiating weapon parameters through SourceObject.

---

## Key Design Points

1. **Three-tier responsibility separation** — Definition: immutable configuration / Instance: runtime state / Manager: network synchronization
2. **AbilitySet automation** — Automatically granted on equip, automatically revoked on unequip, no manual GA lifecycle management
3. **FastArray replication** — Equipment list replicated via FFastArraySerializer, only syncs deltas and changes
4. **SourceObject tracing** — Runtime GA can retrieve equipment configuration through SourceObject, no hardcoded checks needed
5. **Spread/Heat curve-based** — Spread behavior is composed of curves and multipliers, data-configurable for different feel
