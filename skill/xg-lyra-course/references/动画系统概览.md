# Animation System Overview

## Overview

Lyra's animation system adopts a **layered animation architecture**, using AnimBlueprint's LayeredBoneBlend to achieve independent animation control over different body parts (upper body/lower body/head). Combined with dynamic animation nodes and Animation Sharing, it supports efficient animation playback for multiple characters on screen.

---

## Animation Architecture Layers

```
ULyraAnimInstance (Animation Blueprint Instance)
    │  Path: Source/LyraGame/Animation/LyraAnimInstance.h
    │
    ├── Base Pose Layer (Idle/Jog/Sprint)
    │   └── Full body skeleton, affected by movement state
    │
    ├── Upper Body Override Layer (Aim/Shoot/Reload)
    │   └── Blend in to spine/upperarm/hand
    │
    └── Head Override Layer (LookAt/TurnInPlace)
        └── Blend in to neck/head
```

---

## Layered Blend Mechanism

Lyra uses `LayeredBoneBlend` nodes for layered control:

```
LayeredBoneBlend (PerBoneBlendMode)
    │
    ├── Layer 0: Full Body Base Animation (movement, jump)
    │   └── BoneMask: Full body
    │
    ├── Layer 1: Upper Body Actions (aim, shoot, reload)
    │   └── BoneMask: Spine → UpperArm → Hand
    │       BlendIn: 0.1s, BlendOut: 0.2s
    │
    └── Layer 2: Head Actions (look direction)
        └── BoneMask: Neck → Head
            BlendIn: 0.05s, BlendOut: 0.15s
```

This architecture allows the character to independently perform shooting animations with the upper body while running, while the lower body maintains movement animations.

## Dynamic Animation Nodes

Lyra implements runtime-switchable animation nodes, driving animation selection through data:

```
// Pseudo code — Lyra uses custom AnimNodes
AnimNode_LayeredBoneBlendPerBone
    → Runtime switching of animation sets based on GameplayTag
    → Different weapon holding poses are switched through animation sets
    → No need for separate AnimBlueprints per weapon type
```

Weapon type to animation set mapping:
```
Equip weapon → EquipmentManagerComponent notifies AnimInstance
    → AnimInstance switches animation sets (IdlePose / AimPose / FirePose)
    → Each LayeredBoneBlend layer switches to the new animation set
```

---

## Animation Sharing

Lyra integrates UE's Animation Sharing system to optimize animation performance for large numbers of on-screen characters:

```
AnimationSharingManager
    ├── Similar characters share AnimationInstance
    ├── Same frame plays the same animation sequences (hardware instancing)
    └── Significantly reduces animation CPU overhead for multi-character scenarios
```

Trigger conditions:
- Non-player-controlled characters (AI enemies)
- Characters far from the player
- Characters using the same Animation Blueprint

## Animation Blueprint Events

Key events handled by LyraAnimInstance:

| Event | Trigger Condition | Typical Behavior |
|-------|------------------|-----------------|
| OnMontageStarted | Montage begins playback | Switch LayeredBoneBlend weights |
| OnMontageBlendingOut | Montage fades out | Restore to default animation state |
| OnMontageEnded | Montage playback completes | Clean up animation state |
| OnWeaponEquipped | Equipment switch | Update weapon animation set |

---

## Key Design Points

1. **Layered blending** — Different body parts controlled independently, supporting upper body shooting + lower body movement combinations
2. **Animation set switching** — Equipment/weapon switching only updates animation sets, not the entire AnimBlueprint
3. **Animation Sharing** — Non-player characters share animation instances, reducing animation overhead in multiplayer scenarios
4. **Tag-driven** — Animation state driven by GameplayTags, consistent with GAS/Equipment Tag system
