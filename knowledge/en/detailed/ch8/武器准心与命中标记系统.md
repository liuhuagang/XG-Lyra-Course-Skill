# Weapon Reticle & Hit Marker System

## Overview

The weapon reticle system consists of three layers: **WeaponStateComponent** (tracks hit state), **ReticleWidget** (spread rendering), and **HitMarkerConfirmationWidget** (hit feedback markers).

## Weapon State Component (ULyraWeaponStateComponent)

### Core Data

```cpp
struct FLyraScreenSpaceHitLocation
{
    FVector2D Location;       // Viewport screen-space coordinates
    FGameplayTag HitZone;     // Hit zone (TAG_Gameplay_Zone)
    bool bShowAsSuccess;      // Whether the hit was successful
};

struct FLyraServerSideHitMarkerBatch
{
    TArray<FLyraScreenSpaceHitLocation> Markers;
    uint8 UniqueId;           // Batch unique ID
};
```

### AddUnconfirmedServerSideHitMarkers

1. Iterates each FHitResult in FoundHits
2. Projects world coordinates to screen space
3. Determines success via `ShouldShowHitAsSuccess()`:
   - Default: hitting a target from a different team is a success
4. Checks PhysMatWithTags from HitResult for `TAG_Gameplay_Zone` tag to determine HitZone
5. Creates `FLyraScreenSpaceHitLocation` and adds to batch

### ClientConfirmTargetData (Client, Reliable)

Server calls this RPC to confirm hits:
1. Matches the unconfirmed MarkerBatch by UniqueId
2. If `bSuccess == true` and `HitReplaces.Num() != Markers.Num()`:
   - Adds unreplaced hit markers (bShowAsSuccess = true) to `LastWeaponDamageScreenLocations`
3. Removes the batch from `UnconfirmedServerSideHitMarkers`

### FCircumferenceMarkerEntry

```cpp
struct FCircumferenceMarkerEntry
{
    float PositionAngle;        // Angle on the circumference (degrees)
    float ImageRotationAngle;   // Image rotation angle (degrees)
};
```

### SCircumferenceMarkerWidget (SLeafWidget)

Internal Slate widget that draws marker images arranged along a circle in `OnPaint`:
- Computes each marker's position based on PositionAngle
- Applies ImageRotationAngle render transform
- Supports ColorAndOpacity color and transparency

## Hit Marker Confirmation Widget (SHitMarkerConfirmationWidget)

```cpp
class SHitMarkerConfirmationWidget : public SLeafWidget
{
    FSlateBrush PerHitMarkerImage;          // Image for each hit marker
    FSlateBrush AnyHitsMarkerImage;         // Image shown when any hit occurs
    float HitNotifyDuration;                // Notification duration (including fade out)
    TMap<FGameplayTag, FSlateBrush> PerHitMarkerZoneOverrideImages;  // Per-zone marker image overrides

    // Updates HitNotifyOpacity in Tick
};
```

- **PerHitMarkerImage** — Marker image for each hit location
- **AnyHitsMarkerImage** — Marker image shown as long as any hit occurred
- **PerHitMarkerZoneOverrideImages** — Marker image overrides by hit zone (e.g., head/TAG_Gameplay_Zone_Head)
- **Fade Out Effect**: Opacity gradually decreases after HitNotifyDuration ends

## Overall Data Flow

```
Fire → PerformLocalTargeting → Hit Results
  → AddUnconfirmedServerSideHitMarkers (Client records unconfirmed hit locations)
  → OnTargetDataReadyCallback
    → CallServerSetReplicatedTargetData (Send to server)
    → Server validates → GE application
    → ClientConfirmTargetData RPC (Server confirms hits)
      → Hit markers added to LastWeaponDamageScreenLocations
      → Reticle Widget reads and renders
```
