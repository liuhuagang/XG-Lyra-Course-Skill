# Cosmetics System

## Architecture Overview

The cosmetics system controls the addition and removal of character appearance components (hair, equipment, accessories, etc.), supporting runtime dynamic changes and network replication.

Core file: [Cosmetics/](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Cosmetics/)

## Character Part Types

### Animation Layer Selection

Animation layers determine which animation blueprint overlay is used for the character's upper body, lower body, or full body.

```cpp
USTRUCT(BlueprintType)
struct FLyraAnimLayerSelectionEntry
{
    TSubclassOf<UAnimInstance> Layer;
    FGameplayTagContainer RequiredTags;
};
```

- Supports animation layer selection by GameplayTag condition matching
- Different body parts can specify different animation layers (e.g., upper body holding weapon, lower body walking)

### Body Style Selection

Body style determines which skeletal mesh the character uses.

```cpp
USTRUCT(BlueprintType)
struct FLyraAnimBodyStyleSelectionEntry
{
    TObjectPtr<USkeletalMesh> Mesh = nullptr;
    FGameplayTagContainer RequiredTags;
};
```

- Selects mesh by Tag condition matching
- Can be combined with animation layers

### Character Part Definition

```cpp
USTRUCT(BlueprintType)
struct FLyraCharacterPart
{
    TSubclassOf<AActor> PartClass;  // Part class
    FName SocketName;               // Attach socket
};
```

- Each part is an independent Actor attached to a specified socket
- Supports runtime add/remove

## FastArray Replication

The part list uses FastArray serialization for efficient network replication:

```cpp
USTRUCT()
struct FLyraCharacterPartEntry : public FFastArraySerializerItem
{
    FLyraCharacterPart Part;
    TWeakObjectPtr<AActor> SpawnedActor;  // Spawned part Actor
};
```

- Only syncs add/remove/change operations, not the entire array
- Client spawns or destroys part Actors on demand in `OnRep`

## Dual-Component Architecture

The cosmetics system is orchestrated by two components working together: Controller and Pawn.

### Controller Side

[LyraControllerComponent_CharacterParts.h](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Cosmetics/LyraControllerComponent_CharacterParts.h)

- Manages addition and removal of character parts (authority server)
- Adds parts via `AddCharacterPart`, removes via `RemoveCharacterPart`
- Part list synced to client via `OnRep_PartList`
- Supports debug cheats: `AddCheatPart`, `ClearCheatParts`

```cpp
UCLASS()
class ULyraControllerComponent_CharacterParts : public UControllerComponent
{
    void AddCharacterPart(const FLyraCharacterPart& Part);
    void RemoveCharacterPart(FLyraCharacterPart Part, bool bRemoveAll = false);

    UPROPERTY(ReplicatedUsing=OnRep_PartList)
    FLyraCharacterPartList PartList;
};
```

### Pawn Side

[LyraPawnComponent_CharacterParts.h](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Cosmetics/LyraPawnComponent_CharacterParts.h)

- Responsible for spawning and destroying part Actors
- Handles part attachment sockets and animation tag synchronization

```cpp
UCLASS()
class ULyraPawnComponent_CharacterParts : public UPawnComponent
{
    void AddCharacterPart(const FLyraCharacterPart& Part, int32& PartHandle);
    TArray<FLyraAppliedCharacterPart> AppliedParts;
};
```

## Workflow

1. `AddCharacterPart` called on Controller component
2. Server adds the part to `PartList` FastArray
3. `OnRep_PartList` triggers client sync
4. Pawn component receives and spawns part Actor via `SpawnActor` (deferred)
5. Spawned Actor attaches to the specified Socket
6. Cosmetic animation tags are applied, affecting animation layer selection
