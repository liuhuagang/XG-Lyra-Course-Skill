# Accolade System & Kill Feed

## Architecture Overview

The accolade system handles the identification, transmission, and UI announcement of kills, assists, elimination chains, and streaks. It is built on the VerbMessage system using `UGameplayMessageSubsystem`, with GameplayTags driving message routing.

## Accolade System

### Accolade Definition

[Accolade related files]

Accolade definitions are stored in DataRegistry, using the `FLyraAccoladeDefinitionRow` table row:

```cpp
USTRUCT(BlueprintType)
struct FLyraAccoladeDefinitionRow : public FTableRowBase
{
    // Defines accolade display text, icon, Tag, etc.
};
```

Accolade data is registered into DataRegistry via `UGameFeatureAction_DataRegistry` / `UGameFeatureAction_DataRegistrySource`.

### Accolade Broadcast Widget

[ULyraAccoladeHostWidget]

- Inherits `FAsyncMixin`, uses async resource loading
- Receives `FLyraNotificationMessage` messages
- Supports accolade queuing (multiple consecutive accolades displayed in order)
- Mutex logic: new accolades wait if the previous one is not yet complete

```cpp
struct FLyraNotificationMessage
{
    FGameplayTag TargetChannel;
    TObjectPtr<APlayerState> TargetPlayer;     // Specifies target player; empty means visible to all
    FText PayloadMessage;
    FGameplayTag PayloadTag;
    TObjectPtr<UObject> PayloadObject;
};
```

## Kill Feed System

### VerbMessage System

Uses `UGameplayMessageSubsystem`'s `BroadcastMessage` to pass structured messages.

```cpp
USTRUCT(BlueprintType)
struct FLyraVerbMessage
{
    FGameplayTag Verb;
    TObjectPtr<UObject> Instigator;
    FGameplayTagContainer InstigatorTags;
    TObjectPtr<UObject> Target;
    FGameplayTagContainer TargetTags;
    FGameplayTagContainer ContextTags;
    double Magnitude;
};
```

- Server-side singleton component (not spawned per player)

### Standard Message Flow

```
Death → Lyra.Elimination.Message  → AssistProcessor → Lyra.Assist.Message
                                  → ElimChainProcessor → Lyra.ShooterGame.Accolade.EliminationChain.Nx
                                  → ElimStreakProcessor → Lyra.ShooterGame.Accolade.EliminationStreak.N
                                  → EliminationFeedRelay → Lyra.AddNotification.KillFeed
```

### Elimination Message Trigger

In `ULyraHealthComponent::HandleOutOfHealth`:

```cpp
FLyraVerbMessage Message;
Message.Verb = TAG_Lyra_Elimination_Message;
Message.Instigator = DamageInstigator;
Message.Target = ULyraVerbMessageHelpers::GetPlayerStateFromObject(AbilitySystemComponent->GetAvatarActor());
Message.InstigatorTags = *DamageEffectSpec->CapturedSourceTags.GetAggregatedTags();
Message.TargetTags = *DamageEffectSpec->CapturedTargetTags.GetAggregatedTags();

UGameplayMessageSubsystem& MessageSystem = UGameplayMessageSubsystem::Get(GetWorld());
MessageSystem.BroadcastMessage(Message.Verb, Message);
```

### Assist Processor (UAssistProcessor)

[UAssistProcessor]

```cpp
class UAssistProcessor : public UGameplayMessageProcessor
{
    TMap<TObjectPtr<APlayerState>, FPlayerAssistDamageTracking> DamageHistory;

    void OnDamageMessage(FGameplayTag Channel, const FLyraVerbMessage& Payload);
    void OnEliminationMessage(FGameplayTag Channel, const FLyraVerbMessage& Payload);
};
```

- Listens to `Lyra.Damage.Message` to accumulate damage records
- Listens to `Lyra.Elimination.Message` to broadcast assist messages for all players who dealt damage (except the killer)
- Clears damage records for the target after elimination

### Elimination Chain Processor (UElimChainProcessor)

[UElimChainProcessor]

```cpp
class UElimChainProcessor : public UGameplayMessageProcessor
{
    float ChainTimeLimit = 4.5f;                      // Time window
    TMap<int32, FGameplayTag> ElimChainTags;           // Elimination count → Tag
    TMap<TObjectPtr<APlayerState>, FPlayerElimChainInfo> PlayerChainHistory;
};
```

- Listens to `Lyra.Elimination.Message`
- Tracks consecutive elimination count (valid within a time window)
- Resets count if time window is exceeded
- Broadcasts the corresponding `ElimChainTags` when configured threshold is reached

### Elimination Streak Processor (UElimStreakProcessor)

[UElimStreakProcessor]

```cpp
class UElimStreakProcessor : public UGameplayMessageProcessor
{
    TMap<int32, FGameplayTag> ElimStreakTags;           // Streak count → Tag
    TMap<TObjectPtr<APlayerState>, int32> PlayerStreakHistory;
};
```

- Listens to `Lyra.Elimination.Message`
- Tracks consecutive eliminations before being killed
- Ends streak record when the target is eliminated

### Client Broadcast

```cpp
void ALyraPlayerState::ClientBroadcastMessage_Implementation(const FLyraVerbMessage Message)
{
    if (GetNetMode() == NM_Client)
    {
        UGameplayMessageSubsystem::Get(this).BroadcastMessage(Message.Verb, Message);
    }
}
```

- Uses PlayerState's Client RPC to deliver messages to the corresponding client
- Client broadcasts locally via MessageSubsystem upon receipt

## Kill Notification UI

### Kill Feed

- Uses ListView to display kill entries
- Both server and client have EliminationFeedRelay, but no network sync is needed
- Constructs info object per kill entry, sets styles (weapon icon, team color, etc.)
- Supports timed fade-out: event dispatcher bound to timeout event → automatic removal

## Score Processing

Team elimination score component:

- Listens to `Lyra.Elimination.Message` and `Lyra.Assist.Message`
- Score tags modified:
  - TeamInfo: `ShooterGame.Score.Eliminations`
  - PlayerState: `ShooterGame.Score.Eliminations`
  - PlayerState: `ShooterGame.Score.Deaths`
  - PlayerState: `ShooterGame.Score.Assists`
- Scores are distributed via property replication
