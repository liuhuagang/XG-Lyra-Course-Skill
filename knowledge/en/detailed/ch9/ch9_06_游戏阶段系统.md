# Game Phase System

## Architecture Overview

The game phase system uses GAS abilities to drive game flow phase transitions, supporting phase nesting (parent phase persists while child phases switch), observer pattern, and phase mutual exclusion.

- Each phase ability is bound to a GameplayTag
- Tag hierarchy determines parent-child phase relationships

### Tag Match Rules

```cpp
enum class EPhaseTagMatchType : uint8
{
    ExactMatch,     // Exact match, e.g., "A.B" only matches "A.B"
    PartialMatch    // Partial match, e.g., "A.B" matches "A.B" and "A.B.C"
};
```

## Phase Subsystem

[ULyraGamePhaseSubsystem](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/)

```cpp
class ULyraGamePhaseSubsystem : public UWorldSubsystem
{
    // Activate phase
    void StartPhase(TSubclassOf<ULyraGamePhaseAbility> PhaseAbility,
                    FLyraGamePhaseDelegate PhaseEndedCallback = FLyraGamePhaseDelegate());

    // Observe phase start
    void WhenPhaseStartsOrIsActive(FGameplayTag PhaseTag, EPhaseTagMatchType MatchType,
                                   const FLyraGamePhaseTagDelegate& WhenPhaseActive);

    // Observe phase end
    void WhenPhaseEnds(FGameplayTag PhaseTag, EPhaseTagMatchType MatchType,
                       const FLyraGamePhaseTagDelegate& WhenPhaseEnd);

    // Check if phase is active
    bool IsPhaseActive(const FGameplayTag& PhaseTag) const;

private:
    TMap<FGameplayAbilitySpecHandle, FLyraGamePhaseEntry> ActivePhaseMap;
    TArray<FPhaseObserver> PhaseStartObservers;
    TArray<FPhaseObserver> PhaseEndObservers;
};
```

### Activation Flow

1. **Blueprint Start**: `K2_StartPhase` wraps the callback via weak object pointer then calls `StartPhase`
2. **Forward to GA**: `StartPhase` → gets GameState's ASC → `GiveAbilityAndActivateOnce`
3. **Forward to Subsystem**: GA's `ActivateAbility` → `PhaseSubsystem->OnBeginPhase`
4. **Mutual Exclusion**: Iterates `ActivePhaseMap`, uses Tag hierarchy comparison

### Phase Mutual Exclusion Logic

```
Example: Currently active Game.A
- New phase Game.A.1 → Game.A stays active (parent phase), Game.A.1 activates (child phase)
- New phase Game.B   → Game.A is canceled (sibling branch)
- New phase Game.A.2 → Game.A stays active, Game.A.1 is canceled (same-level replacement)
```

Core comparison:
```cpp
if (!IncomingPhaseTag.MatchesTag(ActivePhaseTag))
{
    // Not a child phase relationship → cancel current phase
    GameState_ASC->CancelAbilitiesByFunc(...);
}
```

### End Flow

1. GA's `EndAbility` → `PhaseSubsystem->OnEndPhase`
2. Removes from `ActivePhaseMap`
3. Executes phase end callback
4. Notifies `PhaseEndObservers`

### Observer Mechanism

```cpp
struct FPhaseObserver
{
    FGameplayTag PhaseTag;
    EPhaseTagMatchType MatchType;
    FLyraGamePhaseTagDelegate PhaseCallback;
};
```

- `WhenPhaseStartsOrIsActive`: Calls immediately if phase is already active, otherwise waits for activation
- `WhenPhaseEnds`: Waits until the phase ends then calls
- Note: `WhenPhaseStartsOrIsActive`'s initial check uses partial match, which has a design ambiguity

## Game Phase Examples

### Pregame Phase

- Checks whether to skip the full flow (`ShouldSkipDirectlyToGameplay`)
- Applies global invulnerability effect `GE_PregameLobby`
- Plays waiting GameplayCue (loop sound)
- Sends 3-second countdown
- On end, removes invulnerability → enters combat

### Combat Phase

- Designs game duration and objectives based on player count
- Activates character's Reset ability
- Cleans up scene items (grenades, weapon spawners, etc.)

### Scoring Phase

- Triggered by time limit / score limit / force end
- Global invulnerability, ability usage disabled
- After a delay, calls `PlayNextGame` → ServerTravel starts the next match
