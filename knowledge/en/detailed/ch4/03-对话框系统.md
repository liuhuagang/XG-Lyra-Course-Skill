# Dialog System

## Overview

Lyra's dialog system is built on top of the CommonGame plugin, using a message reception-display pipeline (ReceiveMessage → ShouldDisplayMessage → DisplayMessage) to manage modal dialog display and lifecycle.

## Dialog Lifecycle

```
ReceiveMessage
  → ShouldDisplayMessage (determine if it should be displayed)
    → DisplayMessage (create/show dialog instance)
```

### Message Reception

Dialogs receive messages through the Messaging system, with messages defined in DataAssets of type `ULyraDialogReceiverDefinition`.

### Display Decision

`ShouldDisplayMessage` determines whether to show the dialog, considering factors such as:
- Whether a dialog of the same priority is already displayed
- Current focus state
- Dialog priority

### Dialog Display

`DisplayMessage` is responsible for:
- Getting or creating a dialog instance from the Widget Pool
- Setting dialog content
- Managing focus paths

## Dialog Types

- **Confirmation Dialog** (ULyraConfirmationScreen): Confirm/Cancel operations
- **Loading Dialog** (ULyraLoadingScreen): Loading wait screen

## Widget Pooling

Dialogs use `FUserWidgetPool` to manage dynamically created Widget instances, avoiding frequent creation and destruction. After a dialog closes, the Widget is returned to the pool and reused the next time it is displayed.
