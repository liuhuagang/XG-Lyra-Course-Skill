# Cheat & Debug System

## Overview

Lyra's cheat and debug system is built on UE5's `UCheatManager` framework, with `ULyraCheatManager` providing core cheat commands. Cheat functionality for different subsystems is distributed to independent extension classes via the `UCheatManagerExtension` mechanism. Additionally, an HTTP Server-based external RPC registration component supports remote invocation of in-game commands.

### Core Features

- **Debug Camera Cycling**: `CycleDebugCameras` cycles Normal → Debug → Fixed → Normal. Fixed Camera mode switches via `SetCameraMode` using `NAME_Fixed` / `NAME_Default`
- **God Mode / Unlimited Health**: Implemented via `ULyraAbilitySystemComponent`'s dynamic GameplayTag mechanism, using `AddDynamicTagGameplayEffect` to apply `Cheat_GodMode` / `Cheat_UnlimitedHealth` tags
- **Damage / Heal**: Via `SetByCaller` GameplayEffect, tags are `LyraGameplayTags::SetByCaller_Damage` / `SetByCaller_Heal`
- **Self-Destruct**: Via `ULyraHealthComponent::DamageSelfDestruct()`, checks if Pawn has reached `InitState_GameplayReady` state
- **ASC Debugging**: Provides commands like `CycleAbilitySystemDebug`, `CancelActivatedAbilities`, `AddTagToSelf`, `RemoveTagFromSelf`
- **Editor Auto-Execution**: In `InitCheatManager`, reads `CheatsToRun` array from `ULyraDeveloperSettings`, auto-executes cheat commands in the `OnCheatManagerCreated` phase

## CheatManagerExtension Mechanism

Lyra uses the static `UCheatManager::RegisterForOnCheatManagerCreated` delegate to auto-register extensions during CDO construction. Each extension class calls this delegate in its constructor, and extensions are automatically added when the CheatManager is created.

### Registration Pattern

```cpp
ULyraBotCheats::ULyraBotCheats()
{
    if (HasAnyFlags(RF_ClassDefaultObject))
    {
        UCheatManager::RegisterForOnCheatManagerCreated(FOnCheatManagerCreated::FDelegate::CreateLambda(
            [](UCheatManager* CheatManager)
            {
                CheatManager->AddCheatManagerExtension(NewObject<ThisClass>(CheatManager));
            }));
    }
}
```

## ULyraGameplayRpcRegistrationComponent External RPC

[LyraGameplayRpcRegistrationComponent.h](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Tests/LyraGameplayRpcRegistrationComponent.h) / [LyraGameplayRpcRegistrationComponent.cpp](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Tests/LyraGameplayRpcRegistrationComponent.cpp)

Based on `UExternalRpcRegistrationComponent`'s HTTP Server component, supports external tools remotely invoking in-game commands.

### Core Features

- **HttpExecuteCheatCommand**: `POST /core/cheatcommand`, parses `"command"` field from JSON Body, executes via `ALyraPlayerController->ConsoleCommand()`
- **HttpGetPlayerVitalsCommand**: `GET /player/status`, returns player health and inventory info
- **HttpFireOnceCommand**: `POST /player/status`, example RPC (TODO status)

### Registration Layers

- `RegisterAlwaysOnHttpCallbacks`: Core commands always available
- `RegisterFrontendHttpCallbacks`: Frontend lobby phase (TODO)
- `RegisterInMatchHttpCallbacks`: In-match

### Singleton Pattern

Implemented via static `ObjectInstance` pointer and `GetInstance()` method; `AddToRoot()` prevents GC.
