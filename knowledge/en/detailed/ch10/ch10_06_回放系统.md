# Replay System

## Overview

Lyra's replay system is built on UE5's DemoNetDriver replay framework. `ULyraReplaySubsystem` manages core functions such as recording, playback, and cleanup. Blueprint async nodes are provided for querying available replay lists. During playback, `ALyraReplayPlayerController` automatically follows the recorder's Pawn to switch viewpoint.

## ULyraReplaySubsystem

[LyraReplaySubsystem.h](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Replays/LyraReplaySubsystem.h) / [LyraReplaySubsystem.cpp](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Replays/LyraReplaySubsystem.cpp)

`UGameInstanceSubsystem`, serving as the GameInstance-level replay management entry point.

### Core Methods

- **DoesPlatformSupportReplays**: Checks the `Platform.Trait.ReplaySupport` GameplayTag via `ICommonUIModule::GetSettings().GetPlatformTraits()` to determine if the current platform supports replays
- **PlayReplay**: Plays the specified replay via `GetGameInstance()->PlayReplay(DemoName)`
- **RecordClientReplay**: Triggers `GetGameInstance()->StartRecordingReplay()` to start recording, then reads the retention count from `ULyraLocalPlayer`'s local settings and triggers old replay cleanup
- **CleanupLocalReplays**: Creates a replay streamer via `FNetworkReplayStreaming::Get().GetFactory().CreateReplayStreamer()`, enumerates all replay streams, sorts them, and deletes old replays exceeding the retention count
- **SeekInActiveReplay**: Delegates to `UDemoNetDriver::GotoTimeInSeconds()`
- **GetReplayLengthInSeconds** / **GetReplayCurrentTime**: Delegates to `UDemoNetDriver` to get replay duration and current position

### Data Structures

- **ULyraReplayListEntry**: UObject wrapping `FNetworkReplayStreamInfo`, providing BlueprintPure access methods (`GetFriendlyName`, `GetTimestamp`, `GetDuration`, `GetNumViewers`, `GetIsLive`)
- **ULyraReplayList**: Collection of replay query results, contains `TArray<TObjectPtr<ULyraReplayListEntry>> Results`

## UAsyncAction_QueryReplays

[AsyncAction_QueryReplays.h](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Replays/AsyncAction_QueryReplays.h) / [AsyncAction_QueryReplays.cpp](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Replays/AsyncAction_QueryReplays.cpp)

Blueprint async node for querying available replay lists:

1. Static factory method `QueryReplays` creates instance
2. `Activate()` creates a `ReplayStreamer`, calls `EnumerateStreams` to query
3. `OnEnumerateStreamsComplete` iterates results, creates `ULyraReplayListEntry`, adds to list, sorts descending by timestamp, broadcasts `QueryComplete` delegate

## ALyraReplayPlayerController

[LyraPlayerController.h](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Player/LyraPlayerController.h#L143-L164) / [LyraPlayerController.cpp](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/Player/LyraPlayerController.cpp#L549-L603)

PlayerController used during replay playback, automatically follows the recorder's Pawn to switch viewpoint.

### Registration

In [LyraGameMode.cpp](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Source/LyraGame/GameModes/LyraGameMode.cpp#L39):

```cpp
ReplaySpectatorPlayerControllerClass = ALyraReplayPlayerController::StaticClass();
```

### Following Logic

- **Tick**: Checks `FollowedPlayerState` validity each frame; when invalid, gets `RecorderPlayerState` from `ALyraGameState` and rebinds
- **RecorderPlayerStateUpdated**: Saves the PlayerState to follow, binds its `OnPawnSet` delegate
- **OnPlayerStatePawnSet**: When the followed PlayerState switches Pawn, calls `SetViewTarget(NewPlayerPawn)` to switch viewpoint
- **ShouldRecordClientReplay**: Returns false, indicating the replay Spectator does not participate in recording
