# Bomberman Gameplay (Top-Down Arena)

## Overview

TopDownArena is a Game Feature plugin in Lyra (`Plugins/GameFeatures/TopDownArena`), implementing a **Bomberman-style top-down arena gameplay**. The characteristic of this gameplay is: the C++ layer only handles infrastructure (attribute definitions, movement, camera, data containers), while the entire game logic is orchestrated through Blueprint and GAS.

## C++ Infrastructure

### Attribute Set

[UTopDownArenaAttributeSet](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Plugins/GameFeatures/TopDownArena/Source/TopDownArenaRuntime/Private/TopDownArenaAttributeSet.h) inherits from `ULyraAttributeSet`, defines four attributes, all using `DOREPLIFETIME_CONDITION_NOTIFY` + `REPNOTIFY_Always` for sync:

| Attribute | Default | Clamp Range | Description |
|------|--------|----------|------|
| `BombsRemaining` | 1.0 | `[0, BombCapacity]` | Remaining placeable bombs |
| `BombCapacity` | 1.0 | `>= 1` | Maximum simultaneous bombs |
| `BombRange` | 2.0 | `>= 1` | Explosion range |
| `MovementSpeed` | 400.0 | `[200, 800]` | Movement speed |

Clamping logic is handled uniformly via `ClampAttribute` in `PreAttributeBaseChange` / `PreAttributeChange`.

### Movement Component

[UTopDownArenaMovementComponent](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Plugins/GameFeatures/TopDownArena/Source/TopDownArenaRuntime/Private/TopDownArenaMovementComponent.h) inherits from `ULyraCharacterMovementComponent`, overrides `GetMaxSpeed()`:

1. Gets ASC via `UAbilitySystemGlobals::GetAbilitySystemComponentFromActor`
2. Checks `TAG_Gameplay_MovementStopped` Tag: returns 0 if set (stop movement)
3. Otherwise reads `MovementSpeed` attribute value as max speed

A typical GAS pattern of **attribute-driven movement speed**.

### Camera Mode

[ULyraCameraMode_TopDownArenaCamera](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Plugins/GameFeatures/TopDownArena/Source/TopDownArenaRuntime/Public/LyraCameraMode_TopDownArenaCamera.h) inherits from `ULyraCameraMode` (`Abstract, Blueprintable`), fixed top-down arena mode:

- `ArenaWidth` / `ArenaHeight`: Arena dimensions
- `DefaultPivotRotation`: Default top-down rotation
- `BoundsSizeToDistance` (`FRuntimeFloatCurve`): Arena size to camera distance mapping curve

`UpdateView` implementation: Evaluates camera distance via curve based on bounding box max side → computes Pivot position → sets View.

**Does not follow the player; locks to the entire arena range.**

### Pickup UI Data

[UTopDownArenaPickupUIData](file:///d:/UPS/GitLab/XGUnrealNote/Courses/Lyra-Deep-Dive/code/Lyra/Plugins/GameFeatures/TopDownArena/Source/TopDownArenaRuntime/Private/TopDownArenaPickupUIData.h) inherits from `UGameplayEffectUIData`, attached to GameplayEffect:

## Blueprint Game Logic

### Bomb Mechanics

Bomb logic is entirely implemented in Blueprint, core assets in `Game/Bombs/`:

- `GA_DropBomb` (GameplayAbility): Bomb placement ability
  - Applies `GE_DecrementBombsRemaining` on placement to reduce `BombsRemaining`
  - Checks `Ability.ActivateFail.CellAlreadyContainsBomb` Tag to prevent placing multiple bombs in the same cell
- `B_Bomb_Base` / `B_Bomb_Standard`: Bomb Actor base class and standard bomb
- Bomb three states: **Placed** → **Burning** → **Exploding**
- Explosion logic:
  1. Four-direction recursive explosion, each step propagates to the adjacent cell until max explosion radius
  2. Each direction has a `bool` array controlling whether to continue recursion (stops on obstacle)
  3. Overlap detection: static mesh (block) → empty cell (spawn fireball) → other bombs (trigger chain) → destructibles (random pickup) → character (deal damage)
- Applies `GE_IncrementBombsRemaining` after explosion to restore `BombsRemaining`
- Uses `EndOverlap` detection to prevent self-blocking when placing bombs

### Pickups

Pickups are defined via GE, located in `Game/Pickups/`:

- `GE_BombRangeUp`: Increases explosion range
- `GE_BombCountUp`: Increases bomb capacity
- On pickup, modifies UI style via Attribute sync
- Uses `GameplayCue.TopDownArenaGame.PickupAcquired` to trigger pickup effects

### Experience & GameMode

Uses Lyra standard mode, no C++ GameMode:

- `B_TopDownArenaExperience` / `B_TopDownArena_Multiplayer_Experience` defines experience and multiplayer support
- `B_TopDownArena_GameComponent_Base` / `B_TopDownArena_GameComponent_Lives` / `B_TopDownArena_GameComponent_SpawnLocalPlayers` manages game rules
- `DA_TopDownArena_Splode` / `DA_TopDownArena_Multiplayer` as Playlist data assets

### Input Assets

Defines top-down Bomberman-specific input mappings, supporting bomb placement, movement, and other operations.

### UI Layout

Uses the UIExtensionPoint system to dynamically compose HUD:
- `TopDownArena.ExtensionPoint.AbilityBar`: Ability bar
- `TopDownArena.ExtensionPoint.Players`: Player list
- `TopDownArena.ExtensionPoint.StatsBar`: Stats bar

`OnAddOrRemoveExtension` callback instantiates or removes widgets based on Data type, binds attribute data via `ConfigureWidgetForData`.

### Level Generator

Parametrized grid generator, suitable for `L_TopDown_LocalMultiplayer` level. Computes grid then places destructibles.

### Teams & Scoring

- Supports 4 teams (`B_TopDownArena_GameComponent_Base` manages scoring)
- Phase switching system manages game flow (Waiting → Ready → InProgress → Ended)
- Character selection screen

## GameplayTags

| Tag | Purpose |
|-----|------|
| `Ability.ActivateFail.CellAlreadyContainsBomb` | Prevents placing multiple bombs in the same cell |
| `GameplayCue.TopDownArenaGame.PickupAcquired` | Pickup acquisition GC notification |
| `GameplayCue.TopDownArenaGame.UserMessage.WaitingForPlayers` | Waiting message |
| `GameplayCue.TopDownArenaGame.UserMessage.GetReady` | Ready message |
| `GameplayCue.TopDownArenaGame.UserMessage.GameOver` | Game over message |
| `TopDownArena.ExtensionPoint.*` | UI extension point definitions |

## Architecture Characteristics

- **Minimal C++ Layer**: Only 5 classes, approximately 280 lines of code, handles numerical framework and core mechanism interfaces
- **BP Layer Orchestration**: Bombs, pickups, GameMode, Experience all use Blueprint
- **GAS-Driven**: GameplayEffect manipulates AttributeSet, GameplayCue handles visual feedback
- **Game Feature Self-Containment**: Complete self-contained gameplay plugin
